# 项目复盘：踩坑记录与后续铺垫

本文沉淀 PushCube 模仿学习项目从环境搭建到量化交付全过程中真正遇到的问题与结论，
供后续复现与扩展（强化学习、离线 RL、世界模型）参考。

## 1. 环境适配层

| 问题 | 现象 | 解决方式 |
|---|---|---|
| PyTorch CUDA 与驱动不匹配 | 安装 `torch cu132` 后无法调用 GPU（驱动仅支持 12.4） | 固定 `torch 2.6.0+cu124` / `torchvision 0.21.0+cu124`；cu124 是与驱动匹配的最高官方 wheel |
| LeRobot 插件不被自动发现 | 训练时找不到 `push_cube` 环境 | 在导入 LeRobot 训练入口**之前**先导入兄弟仓库的 `lerobot_push_cube_env` 完成注册 |
| 离屏渲染 | 无显示器环境下 MuJoCo 报错 | 统一设置 `MUJOCO_GL=egl`、`PYOPENGL_PLATFORM=egl`、`EGL_PLATFORM=surfaceless`、`LIBGL_ALWAYS_SOFTWARE=1` |
| bf16 与 rollout 不兼容 | 评估时张量 `.numpy()` 报错 | 策略统一用 fp32 + TF32；配置中 `mixed_precision: "no"` 必须加引号 |
| 动作预处理管线误用 | 推理时用了默认 pipeline 导致结果错误 | 评估严格使用 checkpoint 自带的 `policy_action_to_transition` / `transition_to_policy_action` |
| 环境变量被多层 shell 吞掉 | 后台命令从 `/` 起执行、heredoc 被破坏 | 每条后台命令自带 `cd`；长文本用 base64 传输 |

## 2. 数据格式层

| 问题 | 现象 | 解决方式 |
|---|---|---|
| 字段映射 | 环境输出 `image`/`state`，LeRobot 期望 `observation.images.main`/`observation.state` | 在包装层做显式键映射，并按 `stats.json` 处理动作 |
| 动作重复反归一化 | 评估时二次反归一化，动作幅度被放大 | checkpoint 的 postprocessor 输出已是 raw action，**不要**再次处理 |
| 合并数据导出冲突 | 重复 concatenate、两个导出进程互相覆盖 | 杀掉旧进程，单次切片，后台串行导出 |
| 初始状态重复 | 每回合从同一初始态开始，评估方差失真 | 每回合注入随机偏移，固定种子保证可复现 |
| 数据规模上限 | 期望 100 条演示，实际合并后仅 63 条成功样本 | 诚实记录约束，用 20/40/63 三档做数据量消融，不伪造数据 |

## 3. 训练调参层（ACT 高频踩坑）

1. **动作反归一化错误**：推理时忘记对模型输出反归一化，直接输入环境会导致动作幅度极小，
   模型看似不动——这是最高频错误。本仓库统一依赖 checkpoint 自带 postprocessor 处理。
2. **时间步不对齐**：ACT 输出未来多步动作，环境执行时要按 `n_action_steps` 消费动作队列，
   **不要每步都重新推理**，否则动作断续、方向翻转率上升。
3. **不要盲目加大 chunk**：简单任务 chunk 过大反而降精度。实测 chunk 4/8/16/20/30/40/50
   的成功率为 13/13/23/30/40/60/60%——本任务在 40 附近才出现突破，先前"8-16 最优"的
   经验不适用于本数据集，必须以实测为准。
4. **小数据过拟合**：chunk20 训练到 24000 步时成功率从 36.7% 掉到 20%，训练 loss 降至
   0.030。小数据集不要盲目加步数，优先用预训练编码器与数据增强缓解。
5. **不要修改环境动作空间**：全程保持末端笛卡尔增量控制 `[dx,dy,dz,gripper]`，
   不要改成关节角度控制，避免滑向底层控制范畴。

## 4. 关键结论沉淀

* **ACT 的价值在轨迹连贯性，不在单帧拟合**：验证集动作 MSE 上 BC 反而略低
  （3.24e-06 vs 3.71e-06），但 ACT 的位置误差低 55%（5.55cm vs 12.25cm）。
  分块规划抑制了逐帧重规划的累积抖动。
* **评估协议必须统一**：所有对比都在同一批 50 个固定种子上进行，否则成功率不可比。
* **checkpoint 选择很关键**：chunk40 训练过程中各 checkpoint 成功率 44%→30%→60%→50%
  波动明显，最终 004000 的 50% 是跨协议稳健值，不能只看单点最优。

## 5. 待优化点与后续铺垫

| 方向 | 现状 | 下一步 |
|---|---|---|
| 强化学习微调 | 尚未开展 | 用 SAC/TD3 在模仿策略基础上做在线微调，突破模仿学习上限 |
| 离线 RL | 尚未开展 | 用 CQL/IQL 利用专家数据之外的次优轨迹，缓解分布偏移 |
| 世界模型 | 尚未开展 | 学习 PushCube 动力学模型，用模型预测辅助长时程规划 |
| 数据扩展 | 仅 63 条成功演示 | 扩展采集管线，目标 200+ 条；同步验证数据量-性能曲线是否继续上升 |
| 视觉骨干 | ResNet18（ImageNet） | 尝试更大的预训练骨干或视频序列表征，提升方向控制精度 |

所有后续实验将继续沿用本仓库的固定评估协议与量化指标（成功率 / 完成步数 / 距离误差），
确保策略谱系横向可比。
